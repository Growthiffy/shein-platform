## Frontend

We are building a copy of the Shein company style.

### Landing (entry point)

- Animated background: different fashion-related pictures rotating in the background.
- One prominent button: "Get Started" (or a better unique word).
- Clicking "Get Started" shows a choice: new user or already an account holder
  (Sign-In / Sign-Up).

### After Sign-In — first impression

- Show a screen with a luxury look that builds trust: the member must feel this
  is a real platform and a real project.
- Add a watermark or background picture for a polished website feel.

### Sign-Up flow

- User signs up with a real email and a password.
- As soon as they click Sign-Up, the system emails them a verification code.
- Entering the correct code lets them into the site.

### Main navigation (after Sign-In)

Four main buttons on a clean, real-looking home:

- Product Analyst
- Invest
- Community
- Mentor

## Product Analyst

Clicking Product Analyst opens a portfolio similar to what we were running for
clients on the previous platform. It should feel like a working site.

### First-time popup

- A diagram popup appears explaining how the system works.
- User can close it with (X).

### Profile section

- Username — user sets it, like Telegram.
- Account balance — shows the new-registration reward of $20.
- Level — shown as "Beginner".
- Daily basic salary — $230/day.
- Commission (Dividends):
  - 1.2% on analysing a normal product.
  - 23% on analysing a latest-collection product.

### Level ladder (3 levels)

| Level     | Daily salary | Min. balance | Normal commission | Latest commission |
|-----------|--------------|--------------|-------------------|-------------------|
| Beginner  | $230         | $0           | 1.2 %             | 23 %              |
| Silver    | $500         | $1 000       | 2 %               | 28 %              |
| Gold      | $750         | $2 000       | 4 %               | 35 %              |

If the user does not deposit funds, they must start at Beginner.

### Deposit / Withdrawal buttons (below profile)

- Deposit: when the user deposits, a slip is shown in a professional style so
  the user feels assured the funds have been deposited.
- Withdrawal: similarly, a withdrawal receipt is shown after a withdrawal.
- Deposit screen: company-side wallet addresses are provided from the backend
  and shown to the user, along with proper deposit history.
- Withdrawal screen: the user sets up their own payout wallet (like the
  previous platform) and has proper withdrawal history.

### Side buttons on the profile

- Product Analyst
- Analyst Product History

### Product card layout

```
Brand name:     Vogue
Product name:   Tie
Original price: $1000
Buying rate:    $988
[ BUY ]
```

After the user submits (buys):

```
Product name: Tie
Sale price:   $1000
Profit:       12 %
```

### Analyst cycle rules

- 27 products per cycle.
- User views the product and its price; after analysis, the user submits.
- The commission (Dividends) is then shown and credited to the account.
- A comment section is below — the user must write a comment; only then does
  the product submit and the commission get added.
- Price is auto-generated by the system based on the user's account balance.
- Price stays stable until we (admin) manually select a product from the
  backend that should show a negative result for that user.
- Analyst history shows completed and pending products in a proper way.

### Demo account

- Top-right corner shows a Demo Account button.
- The demo is pre-arranged (automatic sequence).
- Build 4 different scenarios so the client can learn how it works.
- The demo stays as we set it; keep backend flexibility to change it later.

### General rule

Keep backend space to change every value in the future.

## Community

- An AI subsystem runs the community; we can also chat ourselves.
- We decide which members chat as AI, which members are real, and which
  members' chats are open but cannot be replied to.
- Add **20 to 25 characters (personas)**.
- Separate groups: one group for daily-base users, another for investors.
- Access control is ours: we decide which users can reach which other users
  / groups.

## Mentor

- The user picks a mentor **once**.
- From then on they chat with that mentor only.
- To change mentor later, the user contacts Customer Support; the admin can
  then grant access via the backend to change mentor.
- Start with **4 mentors**; more details will be discussed later.
